# Native agentsub admission

This branch adds merchant admission to Tallyhand's existing authentication. Agents keep their native Clerk OAuth sign-in, API, MCP, browser, workspace ownership, roles, and complete tool catalog. No upstream credential import or per-command charge is introduced.

Configure `AGENTSUB_MERCHANT_ID`, `AGENTSUB_OFFER_ID`, and `AGENTSUB_MERCHANT_KEY` (merchant credential scoped `access:check`) on the Next.js server. For `TALLY_STORAGE=convex`, configure the same values plus `CLERK_SECRET_KEY` and the existing `TALLY_CONVEX_SERVER_SECRET` on Convex. Keep all keys server-only. Obtain actual IDs and the credential from the merchant registration; do not use example identifiers. The endpoint is pinned in code to `https://api.agentsub.dev/v1/access/merchant-check`.

Keep the native Clerk instance and its `oauth_agentid` connection. Admission resolves the AgentID subject from exactly one verified Clerk external account's provider user ID, never from the Clerk `user_*` ID, email, request body, or login hint. The decision must bind the merchant, offer, issuer, and upstream subject, with `allowed: true`, `paymentRequired: false`, and serialized `priceUc: "0"`.

For direct Convex browser access, retain the existing supported Clerk **convex** JWT template, issuer, audience `convex`, subject, and role claims. No session claims or template additions are required. Convex verifies the native JWT before the trusted action fetches the live Clerk user and external AgentID binding. The action stores an account-level decision through an internal mutation. Direct queries and mutations require the same verified Clerk subject's unexpired record, bound to the configured merchant/offer. Browser admission refreshes every 30 seconds; decisions expire within 60 seconds. A scheduled internal mutation invalidates expired records and subscribed query results even when the browser stops refreshing. Native JWT expiry and authentication remain enforced independently. This account-level check does not introspect individual Clerk sessions; session-bound claims such as `sid` are unavailable in custom JWT templates ([Clerk documentation](https://clerk.com/docs/guides/sessions/jwt-templates)). Once classified as an agent, unlinking AgentID cannot convert that account to an admitted human. REST/MCP perform fresh admission through the server bridge when Convex is configured. Existing human role and workspace checks continue to apply.

In Clerk Dashboard → JWT templates → **convex**, set or confirm **Token lifetime: 60 seconds** and record the allowed clock skew (default five seconds). Keep the existing claims. Privately decode a real Convex JWT locally and confirm `exp - iat <= 60`; never paste the token into logs, public decoders, or this patch. Convex must reject the token after expiry, including its configured skew. Previously issued tokens retain their original expiry; shortening the template only affects newly issued tokens, so allow the prior lifetime plus skew before claiming the new bound for every outstanding credential. Test this with a held token by stopping refresh, ending its native Clerk session, and attempting a protected query after that expiry window. Admission clearance revocation is bounded by the 60-second decision TTL; native session revocation also depends on the existing JWT lifetime and verifier clock skew. Short-lived admission records do not make a long-lived native JWT session-revocable. Opaque REST/MCP OAuth credentials continue through the existing live Clerk verifier on each request.

To review and apply the packaged patch from a clean Tallyhand checkout, run `git apply --check /path/to/agentsub/docs/integrations/tallyhand.patch`, then `git apply /path/to/agentsub/docs/integrations/tallyhand.patch`. Review `git diff --check` and the changed files before deployment. The patch contains source, tests, this document, and `.env.example`; it contains no runtime secrets, installed dependencies, or build artifacts. Run `npm ci`, `npx tsc --noEmit`, and the admission/authentication tests before enabling configuration. Use an isolated branch and resolve any baseline conflicts before applying.

Deploy the Convex schema/functions before deploying Next.js. Confirm the Clerk template and server variables before enabling the three admission variables. Then verify a real admitted agent can use browser, REST, MCP, and direct Convex; a denied agent cannot; human viewer writes remain denied; and revoked admission expires within 60 seconds. A verified native agent with no registered clearance (gateway `404 NOT_FOUND`) or a frozen/restricted cap policy (`403 CAP_EXCEEDED`) receives a controlled denial and can sign out, switch accounts, retry, or return home. Public landing, login, docs, and share pages are outside the workspace browser gate. Network failures and malformed or mismatched decisions remain verification failures and deny access. Requests have a five-second timeout and reject redirects. No private upstream errors are returned or logged.

No deployment, billing operation, DNS change, or credential has been performed by this preparation branch.
